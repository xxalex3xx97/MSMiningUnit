Developer Reference

Overview

Reference for Main Sequence Demo (Steam, Unreal Engine 5.7, shipping build, IoStore, unencrypted) built from reverse engineering, UE4SS probes and the MiningBenchMod project (<repo>). It documents how the game simulation works, which classes, functions and input commands exist, what each one does, and how the mod uses them.

Key consequence: input commands are the only way to change the simulation. Writing a property on a sim object only changes your local copy. In co-op that desyncs. The mod therefore sends the same commands the UI does.

Game architecture

Lockstep simulation & co-op

INFERRED

Co-op is deterministic lockstep. Every machine runs the full sim, only inputs travel. Actor streaming (what you see) is purely local presentation. Rules for mods: do not mutate sim state locally, send input commands, keep logic deterministic. The mod must not interfere with co-op.

Input command system

All gameplay actions are InputCommand objects pushed to the controller's queue. They are created via CreateInput* static factories (or NewObject for native-only ones), then sent with AddInputCommand.

DMSPlayerController:AddInputCommand

VERIFIED
AddInputCommand(ReceiverId:int, Cmd:InputCommand) // native thunk 0x144211920 -> FUN_1442609d0

Sets cmd+0x38 = ReceiverId and appends to the controller queue at +0x768 (AccumulatedPlayerInput). The flush (FUN_144265260) drops any command whose cmd+0x28 type id is 0, serialises the type id + payload and replicates it. The receiver id selects the target sim object: a ship id for ship commands, the player object id (2325) for player/map commands.

Commands created with a CreateInput* factory have the type id set. Commands built with NewObject (no factory exists) leave +0x28 = 0 and are silently dropped unless the mod writes the id by hand (see ShipMovementInputCommand).

ViewInput steering

VERIFIED
ViewInput.CreateInputView(ControlMode=SHIP(1), ViewRotation) -> AddInputCommand(PilotConsole id, cmd)

ViewRotation is an aim offset relative to the ship nose, not an absolute rotation. The ship turns at a rate growing with the offset; there is a ~7 deg dead zone; (0,0) stops rotation. This is how the mod rotates unpiloted ships (view_send, view_zero, zero_all). The receiver is the ship's PilotConsoleObject (pilot_console_of).

SetThrottleInput controller, not a command

VERIFIED
DMSPlayerController:SetThrottleInput(value:int) // thunk 0x144213c40 -> FUN_144263ca0

Only stores ctrl+0x80c = value and sets the dirty flag ctrl+0x808. The controller tick (FUN_144261794) turns a dirty input into a ShipMovementInputCommand addressed to the PlayerObject id (cmd+0x38 = PlayerObject+0x30). Per-frame state, not per-ship. Does not work for unpiloted ships (that is why the mod builds the command itself).

ShipTeleportInput warp / teleport

VERIFIED 
ShipTeleportInput {
  bSetTarget  = 1      // 1 = only set the jump target (game then charges + warps); 0/other combos = instant teleport
  bClearTarget= 0
  NewLocation = PVector{X,Y,Z .Value}      // fixed-point, chunk-relative
  NewQuat     = {W=65536, X=0, Y=0, Z=0}
  NewChunkLocation = IntVector
  NewSolarSystem   = int (sector.ParentID)
}   -> AddInputCommand(shipId, cmd)

The player's manual warp wraps it: SetPilotingInput(receiver=2325, bNewPiloting=1, ConsoleID) → ShipTeleportInput(ship) → SetPilotingInput(bNewPiloting=0). With bSetTarget=1 the ship gets bJumpTargetSet=1 and the jump target fields, no movement yet. With the full sequence and no further commands the ship teleports instantly and costs no warp fuel (FUELWARP: consumed = no).

SetPilotingInput

VERIFIED
SetPilotingInput(receiver = player object id, bNewPiloting:bool, ConsoleID:int)

Seats / unseats the player in a console. The "seat hack" (piloting an unpiloted ship by sending this with a ship's console id) works but the user dislikes it; removed in the final warp flow.

ShipFiringInput

VERIFIED
ShipFiringInput{bPrimary, bSecondary} -> AddInputCommand(shipId)

Fire groups. Mining laser = primary, item scooper / tractor beam = secondary. The mining cannon shares the primary group, so the mod fires the laser via its own weapon only. Writing the bFiring flag alone does not fire. Stop silences all weapons. Mining laser range 270 m, tractor 300 m (user-reported).

MapPinInputCommand

VERIFIED
MapPinInputCommand{ObjectId = sector id, bShow, bHide, bDestroy} -> AddInputCommand(2325)

Right-click "mark" on a sector in the galaxy map. The mod hooks AddInputCommand (pre-hook, mb_pin.hpp) to store the last bShow=1 pin id as g_pinned_sector (written to MiningPinned.txt). The hook compares class pointers only (no name strings, no logging) to stay cheap.

Systems

Warp / jump

Native rules (Ghidra)

INFERRED from decompile, CONFIRMED in game for the final flow.

ChangeThrottle(ship, delta, bForce)           // FUN_144283910
  Health < 1                          -> return
  docked (Dock, flag bit30 clear)     -> return
  !bForce: if bAutopilot return; bDockingAutopilot = 0
  bTravelling: if delta >= 0 return; else JumpAnimProgress = 1 (exit-warp)
  cooldown: frame - LastThrottleUpdateFrame <= FlightModel[0x30] -> return
  if no WarpDrive or !bJumpTargetSet:  Throttle = clamp(Throttle + delta, -10, 10)   // normal flying
  else (jump target set):               // Throttle is NOT touched
      if delta < 1 or !bAligned return
      if JumpAnimProgress == 0 and WarpDrive:
          cost = GetJumpCost(ship, JumpTargetLocation, Chunk, SolarSystemId)
          if cost <= GetFuel(WarpDrive): ConsumeFuel(WarpDrive, cost); OnJumpStartCharging; JumpAnimProgress = 1

ship tick: if JumpAnimProgress > 0: JumpAnimProgress++; UpdateJumpChargeProgress(...)
           when JumpAnimProgress >= RequiredChargeToJump -> FUN_144286920 (start real warp, OnJumpStart)
           if bJumpTargetSet and JumpAnimProgress == 0:
               bInsufficientWarpFuel = GetFuel < GetJumpCost ; bAligned = dot(forward, dirToTarget) > RequiredAlignmentToJump
  • No pilot is required. Requirements: Health>0, not docked, not on autopilot, not travelling, WarpDrive present, bJumpTargetSet, bAligned, fuel ≥ cost, throttle cooldown elapsed, a +1 throttle command.
  • Fuel is removed in one lump at charge start (nothing at arrival). GetJumpCost = length of the fixed-point delta vector (chunk delta*65536 + loc) scaled by a constant, >>16, minimum 1 (measured cost 5). It does not use FlightModel.WarpFuelConsumption. Mod rule: 1 warp-fuel item = 50 km; drive max 100.
  • Autopilot jumps by itself (FlyTowards FUN_144285240) only to a dock object (order.Dock / TargetDockID); the solar system comes from the dock object. No sector or map-pin target feeds it. It sets the jump target ~7 s after autopilot on and sends no command. pos = tgt - dir * FlightModel.WarpArrivalDistance. Same fuel check/consume as above. So dock trips need no mod warp code.
  • Arrival point per sector is ~deterministic: fixed spot at distance WarpArrivalDistance (Rich 1008: 91.75M raw) with ~4000 raw jitter.

Final mod flow (variant "e", warp_real_cmd, commit 7d94fcb + ef7b1a8)

  1. Undock first if docked (job_start undock); queue behind other warping ships (g_wr_wait, one g_wr state at a time).
  2. ShipTeleportInput{bSetTarget=1, sector arrival, sector chunk, sector.ParentID} → ship has a jump target.
  3. Own auto-aim (wr_e_aim): position delta rotated by the ship quaternion → view_send aim offset until bAlignedWithJumpTarget=1.
  4. Build ShipMovementInputCommand{DeltaThrottle=+1} with type id 0x3a, AddInputCommand(shipId) (send_ship_throttle).
  5. The game charges (JumpAnimProgress 1→30), consumes drive fuel, warps. Timeouts 60 s (wr_start) / 90 s (mining). warp_cancel(sid) aborts and clears the queue (STOP ALL).
Instant fallback warp_sector:<id|pinned> (mb_warp.hpp) does the teleport without fuel or travel; kept for the Dev Menu only. warp_check verifies the new absolute position 1.5 s later and retries once with the SetPiloting wrapper.

Docking, orders, autopilot

  • VERIFIED The player's dock flow: SetShipAutopilot(ship, true) + SkipToOrder(ship, 0) on the existing DeliverOrder. An order created with NewShipOrderInput alone does not move the ship.
  • DeliverOrder: Dock, DockID, WaitConditions[]; tick FUN_144298b60 uses FlyTowards (dock approach), docks on arrival via FUN_14428c350. WaitOrder / WaitForTimeOrder never fly.
  • Mod job layer (mb_dockjob.hpp): one job per ship: dock_mining (unload), dock_refuel, dock_auto, undock. Stages 3: clear orders, build the refuel/unload list via ob_* (mb_orders.hpp) and filters via pf_* (mb_filters.hpp). Undock uses the old "reuse path" with a leave-dock watch (undock_tick).
  • Busy docks: occupancy is derived (dock_busy: another ship has that DockID/Dock or a job targets it). Status "Waiting for dock", a job still blocked by a busy dock after 30 s ends with "waiting dock". Occupancy exported to the UI (dock_occ_write).
  • Dock time limit (dock_hold_limit, default 300 s, 0 = off): on hit, MS_DLWAIT retry: undock + 30 s wait + redo the same trip kind, up to MINE_DOCK_RETRIES=10; the 11th hit halts non-error ("Dock time limit reached 10 times, undocked, idle").
  • Dock names: DisplayName TextProperty (game-made docks have an empty Name). dock_id can be a number or a name.
  • Game windows: WBP_ShipAutopilot_C opens natively via ShowWidget(...).

Mining

  • Rock list = DMSPlayerController.ScannableHUDMarkers (V-scan). Cached and refreshed every 5-10 s: looping FindAllOf or reflecting every rock each second freezes the game. Cached actor pointers can be freed by streaming → validate with actor_ok() before touching.
  • Fallback list (rock_fallback_merge): FindAllOf(BP_GenericResourceAsteroid_C) when a belt seek requested it (6 s window, at most every 5 s). Residual risk: pointers reused up to 5 s can be freed.
  • Approach (mb_steer.hpp): face_rock then approach_rock; throttle steps 1..10 by remaining distance, brake, stop when surface distance reaches mining_distance. Per-ship g_mvs (move jobs), g_spds (speed monitors), g_sel_rocks. Speed safety abort MV_SPEED_ABORT. Rock contention between ships is allowed; a lost rock = free retry.
  • Weapons (mb_weapons.hpp): set_all_firing, fire_input(group), class_firing. Laser primary, scooper secondary.
  • Loop (mb_mining.hpp): see state machine below. Row logic: each queue row ITEM:n = target ore mined (got counter), n=0 unlimited (until cargo full). Dock only on cargo full or fuel low. Cargo % excludes fuel slots.
  • Mining Unit: our own block + actor BP_MiningMod ("Press F to Use Mining Unit") opens the UMG window WBP_MiningUnit. A cloned building block ("MiningBench") is produced by mods/MiningUnitBlockPak (clone.js, patch_registry.py).

Chunk streaming & chunk hold

VERIFIED

Rocks are actors; actors exist only for loaded chunks. The only streaming source is the local player: DMSPlayerController.LoadChunks() (native FUN_144212f00) centres on PlayerObject+0x94 with radius ViewDistance (2 = 5³ = 125 chunks):

  1. S = FUN_14425f2e0(PlayerObject) (the SolarSystem sim object via registry P+0x28, key P+0xa0).
  2. Every chunk in CurrentLoadedChunks gets level 0.
  3. The cube C±R gets level 1 if Chebyshev distance ≤ 1, else level 2.
  4. If bChunksHidden==0, each chunk is applied and level-0 ones pruned; finally writes PlayerCachedChunkLocation = C.
NativeRVARole
get_system(obj)0x425f2e0object → SolarSystem*
SetLevel(S, &chunkKey, level)0x42512e0if chunk in ChunkMap and +0xfd != 0: chunk+0xa4 = level
Apply(S, &chunkKey)0x424cbc0 (→ 0x424d400)if applied(+0xa0) != target(+0xa4): level 0 despawns, 1/2 create objects; applied = target

Chunk hold (mb_chunkhold.hpp, commit d70be9a) uses exactly SetLevel+Apply to keep a 3×3×3 cube loaded around a far AI ship: 0 → 316 rocks within 1 s, stable, no crash, CurrentLoadedChunks stays 125.

  • Never for the ship the player flies; no hold within CH_NEAR_CH (5) chunks of the player in the same system; the player's own zone (±2) is never set or cleared; per-chunk refcount; cap 150 chunks.

Called from the game thread only (never from delayed Lua callbacks).
  • Belt counters wait 4 s after a set so the actors can appear. Forced rock passes at +1 s and +3 s.

Refuel, cargo & flee

  • Fuels / ores are item ids shared by INI, item objects and Lua UI (docks.txt/items.txt); cargo capacity unknown (probe idea only).
  • Flee on damage (flee_now): hull value drop (350→320 seen; 206→202 triggers) halts the ship and goes home; idle ships check hull in step 0 after MINE_FLEE_GRACE_S; skipped when the player flies the ship (player_flies: PilotID == controller id, partly UNVERIFIED). State machine (MineSt)

 MS_OFF  -- Start --> MS_CHECK --(docked? no undock needed when HOLD/no trip)--> undock
 MS_CHECK : cargo/fuel/hull checks, nothing in range for MINE_BELT_EMPTY_S (empty_t, sum of 5 s periods) -> belt_go
 MS_SEEK  : find rock in radius (rock_in_range), approach; "Arrived, seeking rock"; chunk_hold_update while undocked
 MS_MINE  : face + approach + fire laser/scooper; per-row `got` counter; amount 0 = unlimited
 MS_WARP  : real warp to belt sector (queued), then enter_seek
 trip     : cargo full or fuel low -> go_home -> dock -> unload/refuel (jobs) -> MS_HOLD (dock hold timer)
 MS_HOLD  : hold at dock, dock_hold_limit -> MS_DLWAIT (undock, wait 30 s, retry up to 10) -> HALT
 flee     : hull drop -> halt + home; HALT latched by STOP ALL

Constants: MINE_BELT_EMPTY_S, MINE_FLEE_GRACE_S, MINE_DOCK_RETRIES=10, MINE_DOCK_RETRY_WAIT_S=30, MINE_DIAG_PERIOD_S=120 (removed diags). Hop-bug fix: empty_t was reset every MS_OFF→CHECK pass (committed, b06dfdb).

Gotchas & hard rules

  • Native crashes kill the whole game. Always alive()-check UObjects that may be stale; actor pointers are freed by streaming (actor_ok).
  • A delayed callback (ExecuteWithDelay) that calls FindFirstOf after the action ended crashed with an access violation in process_simple_actions. Do not Ctrl+R mid-callback.
  • Looping FindAllOf / reflection over every rock each second freezes the game: cache + refresh every 5-10 s. first_of is a full UObject walk: cache the controller.
  • Lua string paths: use forward slashes (C:/...); "\U" is an invalid escape and the whole script fails to load. No lua/luac on PATH: syntax is only checked in game (UE4SS console).
  • Desktop logging: io.open a file on the Desktop and an agent can read it directly (truncate on probe press).
  • Always undock before any warp or teleport. Each ship runs its own AI; F4 only commands. Mods must not interfere with co-op; don't restore an old backup over the user's live save.
  • Don't invent requirements: build what the user asked.
